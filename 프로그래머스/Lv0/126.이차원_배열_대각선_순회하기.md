# 이차원 배열 대각선 순회하기

## 문제 설명
2차원 정수 배열 `board`와 정수 `k`가 주어집니다.

`i` + `j` <= `k`를 만족하는 모든 (`i`, `j`)에 대한 `board[i][j]`의 합을 return 하는 solution 함수를 완성해 주세요.

## 제한사항
- 1 ≤ board의 길이 ≤ 100
- 1 ≤ board[i]의 길이 ≤ 100
    - 1 ≤ board[i][j] ≤ 10,000
    - 모든 board[i]의 길이는 같습니다.
- 0 ≤ k < board의 길이 + board[i]의 길이

## 입출력 예

| board | k | result |
| :-- | :-- | :-- |
| [[0, 1, 2],[1, 2, 3],[2, 3, 4],[3, 4, 5]] | 2 | 8 |

## 입출력 예 설명

입출력 예 #1
- 입출력 예 #1의 `board`를 표로 나타내면 다음과 같습니다.

| i \ j | 0 | 1 | 2 |
| :-- | :-- | :--| :-- |
| 0 | 0 | 1 | 2 |
| 1 | 1 | 2 | 3 |
| 2 | 2 | 3 | 4 |
| 3 | 3 | 4 | 5 |

- `i` + `j`가 2보다 작거나 같은 항들의 합은 0 + 1 + 2 + 1 + 2 + 2 = 8이므로 8을 return 합니다.

## 배운점
- 또 다른 문제 해결방법인 중첩 `reduce`문을 통해 가독성이 중첩 `for`문 보다 떨어진다는 것과 중단점 디버깅이 어렵다는 것을 인지하게 되었으며 이로 인해 실무적으로 유지보수성이 좋은 코드라는 것을 알게 되었다.

- `enumerated`는 루프에서 매번 인덱스와 요소를 생성하기 때문에 다차원의 배열 내부에서 사용할 경우 메모리 오버헤드가 발생하여 성능 저하의 원인이 될수 있다.
- 해서 성능이 최우선인 다차원 배열 연산이나 좌표 계산 규칙에서는 `range`로 접근 하는것이 좋고 1차원 배열 루핑시 요소와 인덱스가 동시에 다이렉트로 필요할때 사용하는 것이 좋다는 것을 알게 되었다.

- `for`루프 내부에서 `if`문을 사용했지만 이전 문제에서 조건에 해당하면 반복문을 종료하는것이 아니라 그대로 `continue`를 한다면 `for where`를 사용하는 것이 조금의 가독성 마저 챙길 수 있다.

## 나의 풀이

### 첫번째 풀이
```swift
func solution(_ board: [[Int]], _ k:Int) -> Int {
    
    var result = 0
    
    for i in 0..<board.count {
        for j in 0..<board[i].count {
            if i+j <= k {
                result += board[i][j]
            }
        }
    }
    
    return result
}
```

### 두번째 풀이
```swift
func solution(_ board: [[Int]], _ k:Int) -> Int {
    
    var result = 0
    
    for i in 0..<board.count {
        for j in 0..<board[i].count where i + j <= k {
            result += board[i][j]
        }
    }
    
    return result
}
```
